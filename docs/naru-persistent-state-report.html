Naru change report

Persistent agent state without a growing prompt

Naru now keeps a compact current state in the active prompt. It stores the full agent trace in SQLite and restores older details through an exact run-scoped pointer.

How the research shaped the design

WikiSkill

Keep raw experience recoverable. Promote useful procedures into a curated skill collection. Naru maps this to trace rows, naru skill, and the existing inbox.

SKILL.state

Separate stable instructions from compact changing state. Naru now carries current state and the latest observation instead of a growing reasoning history.

ContextPilot

Move older details out of active context and restore selected parts when needed. Naru uses scoped Event Log pointers for this soft offload.

BEAM

Measure long-term memory behavior with repeatable tasks. Naru adds a standard-library adapter and a fixed six-turn replay for prompt measurements.

How we got here

  1. Read the repository decisions and clear the inbox.

    We reviewed 65 items. We kept 16 and dropped 49.

  2. Study the papers and ContextPilot.

    The common shape was compact state, recoverable experience, and curated procedures.

  3. Keep one store.

    The existing SQLite Event Log already owned ordering, recovery, pruning, and promotion. The change reuses it.

  4. Record a baseline.

    A fixed replay covered ten BEAM question types with six turns each.

  5. Implement and review.

    The first review found seven faults. We fixed marker safety, temporary cleanup, run mixing, empty benchmark slices, sandbox cleanup, retry trace loss, and source lookup speed.

  6. Rerun the full checks and push.

    All offline checks passed. The branch now tracks GitHub at the same commit.
