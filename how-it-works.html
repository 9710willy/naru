Naru stores history in SQLite and loads selected context

Naru puts raw history, tool output, agent trace, claims, and skills in one SQLite Event Log. The Python agent builds each view from current state and selected rows. Coding-agent hooks load the approved doc.

2 · The row type controls where data appears

One table holds several kinds of data. The kind field keeps their read rules separate.

Kind What it stores How it returns Age rule
context_msg, model_turn, note Conversation and saved notes Normal search, outline, and expand Old rows can be pruned
tool_result Large tool output naru show or naru search Old rows can be pruned
agent_reply, agent_observation The model's code and the result it saw Hidden by default. Exact run plus sequence range restores it A promoted item's cited range stays
agent_state Current task state or Codex doc hash Hidden from normal recall Old uncited rows can be pruned
claim, skill Facts and procedures proposed for later sessions Only promoted rows enter the approved doc Decided rows never age out

3 · One turn in the Python agent

agent.py builds the prompt, runs one model-written Python cell, and stores the trace.

1
Build the prompt. It contains the question, source and trace indexes, the kernel digest, the current state, and the latest observation.
2
Get one Python cell. The system asks for a fenced cell. extract_code() also accepts code without fences and gives a first no-code answer one retry.
3
Run the cell. Variables stay in the kernel. Its digest shows names, types, sizes, and source sequence numbers instead of full values.
4
Store the result. Naru appends the reply, printed observation, and any valid state under one run ID. The next prompt keeps the newest state and observation.

5 · Codex receives the latest approved doc

Codex does not reload a changed AGENTS.md block during an existing thread. The plugin uses native start and prompt hooks instead.

Hidden agent_state stores the Codex session ID, doc sequence, and hash. It never stores the user prompt.

Codex tool output stays untouched

Codex 0.152 reports a completed replacement as blocked. An agent can then repeat a write that already ran. The plugin leaves PostToolUse unused and handles approved context only.

6 · Claude Code can spill large tool results

This is a separate PostToolUse hook. It keeps a large command result recoverable while replacing the model-facing copy.

The hook keeps the tool's original response shape. If storage fails, it leaves the full result inline so the tool call still works.

Why the default is 4,000 characters

Measured sample Finding
One day, old 10,000-char threshold 87 skipped outputs between 4,000 and 10,000 chars carried about 129,000 tokens

metrics.py also records outputs that stay inline and later show or search calls. Those facts do not exist in the Event Log. Metrics failures never stop a tool call.

7 · Child-process mode limits crashes

Set NARU_KERNEL=sandbox for a file-backed log.

Default kernel

Runs in the harness process. It supports in-memory benchmark databases.

Model code shares that Python process.

Child-process mode

Opens SQLite in read-only mode. CPU, file size, output, and wall time have limits.

A dead child restarts on the next call and loses its resident variables.

The child still has the user's filesystem and network. Add an operator-supplied jail for that boundary. macOS refuses the address space memory limit, and limits() reports the refusal.

8 · Which research shaped each part

Naru combines ideas from several papers and one research project.

Naru part Research source Idea used
Event Log and Python retrieval Context as an Environment Keep history outside the prompt and load selected evidence through code.
Reviewed skills WikiSkill Keep raw experience recoverable and promote useful procedures.
Compact agent state SKILL.state Separate stable instructions from changing task state.
Scoped recovery ContextPilot Move old detail out of active context and restore only what the task needs.
Long-memory checks BEAM Test recall and reasoning across long chat histories.

Naru combines these parts in one SQLite log. The implementation adds its own review, conflict, and retention rules.

9 · What the benchmark says

Current reference run: LongMemEval-s, 96 questions, Sonnet 5, judge Haiku 4.5.

full sends all history in one call. rag sends the top eight BM25 search hits. naru lets the model search and compute across calls.

Arm Correct 95% range Largest view Calls Model cost / q
naru 72/96 65-83% 2,174t 3.7 $0.3547
full 64/96 57-75% 124,073t 1.0 $0.8036
rag 59/96 51-71% 2,142t 1.0 $0.0753

Naru had the highest accuracy in this run. No pair passed the paired-test cutoff of 0.0167, which is lower because the report tests three pairs. The run does not prove an accuracy winner. The ranking reversed on the smaller Haiku run. rag stayed cheapest.

How to read that result

LongMemEval often asks for one stored fact, so a top-eight BM25 retrieval can do well. The category gap in this run appeared in temporal reasoning and preference following, where the answer needs work across several rows. These category checks were done after the run and remain descriptive.

The page omits the CLI's billed-input field. It does not reconcile across runs. View size and the CLI's own cost stay consistent.

Naru combines several research ideas and adds shared, reviewed memory for coding agents. Read README.md for setup and docs/adr/ for the recorded reasons behind the design. The benchmark uses LongMemEval. Its judge prompt differs from the official benchmark prompt, so the scores track this repository only.
