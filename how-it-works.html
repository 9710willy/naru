What we built · naru

naru, explained by what the code actually does

One idea: the conversation history never enters the prompt. It lives in a database. The model writes Python to reach it, and only what it prints comes back.

1 · The mental model

Two zones. Everything hinges on which zone your data sits in.

Outside the prompt — free

Event Log — SQLite table, one row per turn, each with a stable address seq. Full-text searchable. 

seq 1  user  "I drive a blue Subaru"
seq 2  asst  "Nice car!"
 …  487 turns, 47 sessions …

Python kernel — variables survive between model calls. 

flights = [ …1,200 rows… ]
bulk    = [ …40 hits… ]

Inside the prompt — you pay, every turn

Question: What car do I drive?

resident: bulk: list[40]   ← digest, not data

[obs 2]
<seq 1 user: I drive a blue Subaru>

--- evicted ---
  [3-18] ms.expand(3,18)   ← pointer

97 tokens instead of 124,609.

The kernel holds a 40-row result. The prompt learns only that it exists and how big it is. That single gap is the whole technique.

2 · Why this saves anything

Because an LLM call is stateless — the harness re-sends the whole conversation every single turn.

A 7,000-token page read once, on turn 5

with naru

It also stops the context window filling with stale text — the harder limit, and the one that quietly wrecks accuracy.

3 · One turn, start to finish

This loop is agent.py. Four moves, repeated.

1
Build a small working view. Question + what's resident in the kernel + the last few observations + the eviction index. Typically 100–1,500 tokens.
2
Model replies with one Python cell. No prose, just code.
3
The kernel runs it. Searches hit the log. Big results bind to variables and stay there.
4
Only print() output returns as the next observation. Loop until the model calls submit_answer().

What the model writes — the four verbs

# LOCATE — BM25 over the log, falls back to OR if AND finds nothing
hits = ms.search("Subaru", k=5)

# NAVIGATE — when the question's words don't appear in the history at all
print(ms.outline())          # 47 sessions, 1 line each

# MATERIALIZE — recover an exact span, verbatim, from any address
turns = ms.expand(87, 912)

# COMPUTE — plain Python; nothing here costs a token
best = min(turns, key=lambda t: t.created_at)

# EXPOSE — the ONLY line that costs anything
print(best.content)

4 · The part that isn't just "summarize"

Eviction shrinks the view, never the record.

Compaction (everyone else)

turns 3-18  ──►  "user discussed
                  travel plans"

original text: GONE

You chose what mattered before you knew the question. Wrong guess = unrecoverable.

naru's eviction

turns 3-18  ──►  [3-18] travel plans
                 ms.expand(3,18)

original text: still in the log

The pointer is the point. Any evicted span is one call from coming back verbatim.

The index is tiered so it can't grow linearly. Measured in eviction.py: 60 evictions → 10 index entries, 4 tiers.

Version What changed Score
v1 first working end-to-end run 50.0%

v3 + ms.outline(), + auto-OR search fallback 83.3%

v2 fixed real bugs but moved the score zero — it traded old failures for new ones. Honest result, kept in the record.

The find that produced the jump

Three questions failed with the agent insisting the fact wasn't there. It was. The question said "homegrown ingredients"; the conversation said "basil" and "cherry tomatoes". 

ms.search("homegrown")   → 0 hits   (word never appears)
ms.search("basil")       → 3 hits
ms.outline()             → "…recipe ideas that use fresh
                             basil and mint…"  ← found it

Lexical search can't bridge a vocabulary gap. So we gave it a structural map instead — the same outline-then-expand move the paper calls navigation anchors. +33 points.

What's still failing, and why it's not the harness

2 of 12 remain. One is a flaky empty reply from the CLI. The other: the agent claimed search('Kg2') and search('Bd5') returned nothing, then gave up. 

ms.search("Kg2") → 3 hits    the agent said 0
ms.search("Bd5") → 3 hits    the agent said 0

The search layer was correct. The model hallucinated the failure. That is the paper's own finding — weaker backbones "commit more execution errors or terminate prematurely" — not a bug we can patch in the harness.

6 · Where naru wins, and where it doesn't

Oracle split — history is only 5.6k tokens

Arm Accuracy Net input / q View size
full context 100% 15,140 5,669t
naru (v3) 83.3% 100,206 1,310t

Full context wins here, and it should. A 5.6k history fits in one prompt with room to spare, so there is no pressure to relieve — and naru pays for multiple turns to reach the same facts. Reporting this is the point: a technique that only ever looks good is being measured wrong.

LongMemEval-s, n=24, Haiku 4.5, judge Haiku 4.5. No pair separates on accuracy — paired McNemar puts every comparison between p=0.125 and p=0.625, so at this n the harness cannot tell the three apart. What is not close is cost: rag answers in one call on 1,816 input tokens against naru's 4.4 calls and 73,199, forty times the input for no measurable gain. On this benchmark the kernel does not earn its keep. ADR 0006 records why that is the expected result for LongMemEval's question shape and what would actually test it. The judge is not LongMemEval's official prompt; these numbers track this repo and nothing else.

7 · The code

File Job Its own check
ms.py Event Log: search / outline / expand / sql_query passes
kernel.py persistent namespace, exec, print capture passes
eviction.py Algorithm 1 + tiered index passes
agent.py the turn loop + system prompt passes
backend.py model calls via the claude CLI live
bench.py LongMemEval ingest → judge → score running

Stdlib only — no pip install. Every file runs its own check with python3 <file>; the first four need no network.

Swapping the model

Only backend.py knows about Claude, and its whole contract is one function: 

def backend(prompt: str, system: str | None) -> str

Codex CLI (codex exec), an OpenAI or Gemini SDK call, a local Ollama endpoint — anything matching that signature drops in. The paper swaps six different backbones with the harness held fixed.

Implementation of Context as an Environment: Programmatic Context Management for Long-Horizon Agents, Lin et al., arXiv 2608.21690. Benchmark: LongMemEval (ICLR 2025). Scores above are from our own runs with Haiku 4.5 and an LLM judge that is not the benchmark's official judge prompt — they are indicative of our own progress, not comparable to published leaderboard numbers.
